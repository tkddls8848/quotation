# 결정 0013 — 예적금 상품은 공시에서 받아 오고, 창구 Worker 하나를 둔다

- 날짜: 2026-09-13
- 상태: **적용됨**
- 잇는 결정: [결정 0010](0010-retire-the-server-conversion-path.md),
  [결정 0012](0012-one-folder-per-feature.md)

## 결론

FIRE 계산기에 **지금 가입할 수 있는 예적금 상품 추천**을 넣는다. 상품 목록은
금융감독원 **금융상품 통합 비교공시** 에서 받아 온다. 그러기 위해 오래 비어
있던 `wrangler.jsonc` 의 `main` 에 Worker 를 하나 둔다 — 하는 일은
`/api/fire/products` 로 들어온 요청에 인증키를 붙여 공시 API 로 넘기고, 받은
것을 그대로 돌려주는 것뿐이다.

## 왜 목록을 파일에 적어 두지 않는가

금리는 적는 순간 낡는다. 은행과 저축은행의 예적금 금리는 한 달에 한 번 공시가
바뀌고, 그 사이에도 특판이 뜨고 진다. 저장소에 숫자를 적어 두면 **틀린 금리로
줄을 세우게 된다** — 이 목록의 값어치는 차례가 맞다는 것 하나인데, 그 하나가
무너진다.

공시는 전 은행·저축은행의 정기예금과 적금을 한자리에 모아 두고 기간별 금리까지
준다. "시중 상품을 최대한 많이" 라는 요구에 답이 되는 자료는 이것뿐이다.

## 왜 브라우저가 직접 부르지 못하는가

두 가지가 막는다.

1. **인증키.** 공시 API 는 발급받은 키를 물음표 뒤에 붙여야 답한다. 화면에
   박아 넣으면 누구나 가져다 쓴다. 키가 남의 손에 넘어가면 우리 이름으로
   호출 한도가 소진된다.
2. **CORS.** 브라우저에서 바로 부르면 응답을 읽을 수 없다.

그래서 키를 아는 자리가 하나 필요하다. 그 자리가 Worker 다.

## 무료 계정 전제는 깨지지 않는다

결정 0002·0010 이 `main` 을 비워 둔 이유는 **변환을 서버에서 하지 않기** 위해서
였다. 견적서 한 건에 CPU 73 ms 가 드는데 무료 계정은 요청당 10 ms 다. 그 근거는
그대로고, 변환은 여전히 브라우저의 Rust→WASM 엔진이 한다.

새 Worker 가 그 전제를 건드리지 않는 까닭은 이렇다.

| 걱정 | 왜 괜찮은가 |
|---|---|
| 요청당 CPU 10 ms | 이 Worker 는 몸통을 읽지 않는다. 주소를 표에서 고르고 키를 붙여 넘길 뿐이라 파싱이 없다. 상품과 금리를 맞붙이는 일은 브라우저가 한다 |
| 하루 10만 요청 | 정적 자산에 맞는 요청은 Worker 에 들르지 않는다. 화면을 여는 것만으로는 깨어나지 않고, 깨어나는 것은 <상품 불러오기> 를 누를 때뿐이다 |
| 공시 API 호출 한도 | 응답을 하루 캐시한다 (`cf.cacheEverything`). 공시는 한 달에 한 번 바뀐다 |
| 스크립트 크기 3 MiB | 파일 두 개, 4 KiB 다 |

## 창구가 통로가 되지 않도록

주소를 요청에서 조립하지 않는다. `kind` 와 `group` 은 미리 정한 네 조합의
열쇠일 뿐이고, 표에 없으면 400 이다. 이 창구로 아무 데나 대신 찔러 볼 수 없어야
한다. 실패 문구에도 주소를 담지 않는다 — 물음표 뒤에 인증키가 붙어 있다.

## 어느 폴더에 두는가

공시 API 를 아는 것은 FIRE 기능이므로 `fire/worker/products.ts` 에 둔다. 셸의
`web/worker/index.ts` 는 어느 길이 누구 것인지만 알고 넘긴다. 의존은 셸 → 기능
한 방향이고 (결정 0012), 그 길은 별명이다. 화면 쪽 별명은 `vite.config.ts` 에,
Worker 쪽 별명은 `wrangler.jsonc` 에 있다 — Worker 는 vite 를 거치지 않기
때문이다. 상대 경로로 질러가는 길은 `web/src/boundaries.test.ts` 가 막는다.

## 키가 없으면 어떻게 되는가

상품 추천 칸만 "인증키가 설정되지 않았습니다" 라는 안내로 내려앉고, 계산기는
그대로 돈다. 이 기능이 계산의 전제가 아니라 곁들임이기 때문이다 — 판정은
예전처럼 브라우저 안에서만 이루어지고, 넣은 숫자는 여전히 서버로 가지 않는다.
Worker 로 나가는 것은 "정기예금, 은행, 1쪽" 뿐이고 사용자의 금액·나이·지출은
가지 않는다.

## 무엇을 잃는가

- **화면을 여는 데 필요한 것이 하나 늘었다.** 예전에는 `wrangler` 로 정적 자산만
  올리면 끝이었고, 이제는 대상마다 `wrangler secret put FSS_API_KEY` 를 한 번
  해 두어야 상품 추천이 돈다.
- **공시가 멈추면 이 칸도 멈춘다.** 금리를 우리가 들고 있지 않기 때문이다. 대신
  틀린 금리를 보여 주는 일은 생기지 않는다 — 낡은 숫자를 들고 있는 것보다 없다고
  말하는 편이 낫다고 보았다.
- 우대조건은 문장으로만 온다. 무엇을 채워야 최고 금리를 받는지는 공시가 사람이
  읽는 문장으로 주므로, 우리는 기본 금리로 줄을 세우고 최고 금리는 곁에 적어만
  둔다.
