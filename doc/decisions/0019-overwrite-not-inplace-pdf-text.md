# 결정 0019 — PDF 글자는 제자리에서 고치지 않고 덮어쓴다

- 날짜: 2026-09-21
- 상태: **적용됨**
- 정한 것: [PDF 글자 고치기 화면](../../converters/web/src/pdf-edit-panel.ts)과
  [그 논리](../../converters/web/src/pdf-edit.ts)
- 관련 결정: [결정 0015](0015-both-pdf-to-hwpx-modes.md),
  [결정 0018](0018-browser-only-converters.md)

## 결론

PDF 안의 글자를 **제자리에서 고치지 않는다.** 그 자리를 배경색으로 덮고 그 위에
새 글자를 그린다. 새 글자에 쓸 글꼴과 크기는 고르게 한다.

```text
원래 글자 [BEFORE]  →  [        ] 덮고  →  [고친 글자] 새 글꼴로 그린다
                        (배경색)
```

## 왜 제자리 편집을 하지 않는가

하려다 못 한 것이 아니라 **원리상 되지 않는다.** 이유가 셋이고, 셋 다 우회로가 없다.

| 막는 것 | 왜 |
|---|---|
| 글리프가 없다 | 한글 PDF 는 CID 글꼴을 **서브셋**으로 심는다. 원본에 쓰이지 않은 글자는 모양 자체가 파일에 없어서 그릴 수가 없다 |
| 다시 흘릴 수 없다 | 글자 폭이 바뀌면 줄이 밀린다. PDF 에는 문단·줄바꿈 개념이 없어 재배치가 불가능하다 |
| 고칠 도구가 없다 | `pdf-lib` 에 콘텐츠 스트림 파서가 없다. `Tj`·`TJ` 연산자와 `ToUnicode` 역매핑을 직접 다뤄야 한다 |

첫째가 특히 단단하다. "갑" 을 "을" 로 바꾸려는데 그 문서에 "을" 이 한 번도
쓰이지 않았다면, 그 글꼴에는 "을" 이 없다. 숫자 몇 개를 바꾸는 라틴 문서에서만
되는 기능을 "PDF 글자 수정" 이라 부를 수는 없다.

## 무엇을 약속하지 않는가

화면에 그대로 적는다. 이 셋을 적지 않으면 이 기능은 쓰는 사람을 속인다.

- **원래 글자는 지워지지 않는다.** 덮을 뿐이라 파일 안에 남아 있고 글자를 뽑아
  보면 나온다. **가려야 할 내용을 감추는 용도로 쓰면 안 된다.** 보안 가림
  (redaction)이 아니다.
- **원본과 같은 글꼴을 쓸 수 없다.** PDF 는 쓰인 글자의 모양만 담고 있어서 새
  글자를 그 글꼴로 그릴 방법이 없다. 그래서 글꼴을 고르게 한다.
- **배경이 단색이 아니면 덮은 자국이 보인다.** 무늬·그림·표선 위는 티가 난다.

## 글꼴은 저장소에 담지 않는다

한글 글꼴은 한 벌이 2~14MB 다. 여덟 종이면 39MB 이고, 바이너리는 델타 압축이
먹지 않아 한 번 커밋하면 git 이력에서 되돌릴 방법이 없다. 데스크톱 EXE 와 같은
규칙을 따른다 — **배포할 때 받아서 함께 내보낸다**
([`web/scripts/fetch_fonts.py`](../../web/scripts/fetch_fonts.py), npm 레지스트리,
판본 고정).

그래서 목록도 코드가 아니라 받아 온 자리(`/fonts/fonts.json`)가 갖는다. 못
받았으면 화면이 있는 척하지 않고 PDF 기본 라틴 글꼴과 "내 글꼴 불러오기" 로
물러난다.

전부 SIL OFL 1.1 이라 재배포할 수 있다. 고지는 **글꼴이 제 안에 적어 둔 것**
(`name` 테이블)에서 뽑는다 — npm 패키지가 담은 LICENSE 는 `@expo-google-fonts`
의 경우 **래퍼의 MIT** 이지 글꼴의 OFL 이 아니다. 전문을 못 찾으면 글꼴을 아예
담지 않는다.

맑은 고딕·함초롬돋움처럼 재배포할 수 없는 글꼴은 쓰는 사람이 제 파일을 올려
쓴다. 올린 글꼴도 이 컴퓨터를 벗어나지 않는다 (결정 0018).

## 배치 테이블을 떼고 심는다

`@pdf-lib/fontkit` 은 GPOS 가 빈 껍데기인 글꼴에서 버퍼 끝을 넘어 읽고 죽는다
("Trying to access beyond buffer length"). 나눔고딕·나눔명조·나눔손글씨·도현·
주아·개구가 모두 그렇다 — 한글 글꼴에서 드문 일이 아니라서 그 글꼴들을 목록에서
빼는 것으로는 해결되지 않는다. 쓰는 사람이 제 글꼴을 올릴 때 같은 일이 그대로
일어난다.

우리는 글자를 그려 넣을 뿐이라 합자·커닝 테이블을 쓰지 않는다. 그래서 심기 전에
뗀다 ([`sfnt.ts`](../../converters/web/src/sfnt.ts)). 고치는 것이 아니라 안 쓰는
것을 버리는 것이라 글자 모양은 그대로다.

## 되돌리는 값

작다. `pdf-edit*.ts`·`sfnt.ts`·`fonts.ts` 와 고르기 한 칸, 빌드의 글꼴 단계
하나다. 지워도 나머지 변환기는 그대로 선다.

되돌릴 조건은 하나다. **제자리 편집이 가능해지면** — 브라우저에서 쓸 수 있는
콘텐츠 스트림 편집기와 글꼴 서브셋 확장이 함께 나오면 — 이 방식은 그것의
아랫단으로 물러나야 한다. 그때까지는 이것이 브라우저에서 할 수 있는 최선이다.
