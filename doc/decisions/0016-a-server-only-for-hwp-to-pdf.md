# 결정 0016 — HWP → PDF 에만 서버를 다시 들인다

- 날짜: 2026-09-15
- 상태: **구현·검증 완료, 배포 안 함**
- 관련 결정: [결정 0002](0002-convert-in-browser.md),
  [결정 0010](0010-retire-the-server-conversion-path.md),
  [결정 0012](0012-one-folder-per-feature.md)
- 검증 기록: [converters/VALIDATION.md](../../converters/VALIDATION.md)

## 결론

문서 변환기의 **HWP(5.0) → PDF 한 기능에만** 별도 변환 서버를 둔다.
`converters/server/` 에 그 구성(API 한 개 + 격리 컨테이너 한 개)과 검증이 들어 있다.
공개 서버를 띄우지는 않았다. 화면은 서버에 닿지 못하면 그 사실을 적고 기능을 잠근다.

견적서 변환은 그대로 브라우저다. PDF 편집·HWPX 생성·읽기도 그대로 브라우저다.

## 왜

브라우저만으로는 **확실하게** 안 된다. 공개된 HWP 파서는 포맷의 일부만 읽거나
(hwp.js), 렌더러가 없거나(hwp-rs, openhwp), 0.x 이고 글꼴이 없으면 배치가
달라진다(@rhwp/core). 한글 기본 글꼴인 함초롬체는 웹 재배포 권리가 불분명하다.

| | A. 브라우저 파서 | B. 데스크톱 한글 자동화 | C. 변환 서버 |
|---|---|---|---|
| 파일이 나가는가 | 안 나간다 | 안 나간다 | **나간다** |
| 한글 설치 | 불필요 | **필요** | 불필요 |
| 지원 범위 | 포맷 일부 | 가장 높다 | 실측 30/36 |
| 우리가 고칠 수 있는가 | 파서를 떠안는다 | 한컴에 달렸다 | 엔진은 상류, 격리는 우리 것 |

B 는 이미 있다(`converters/desktop/hwp-to-hwpx.ps1`). 한글이 깔린 PC 가 있는
사람에게는 그것이 여전히 가장 정확하다. 없는 사람을 위해 C 를 만든다.

## 결정 0010 을 뒤집는 것이 아니다

0010 이 지운 것은 **같은 변환(견적서)을 두 곳에서 하던 두 벌 구현**이었다.
브라우저와 서버가 같은 일을 하니 코어가 두 벌이 될 위험이 있었고, 그래서 서버를
지웠다. 여기서 들이는 것은 **브라우저가 못 하는 일 하나**를 위한 한 벌이다.
겹치는 구현이 없으므로 0010 의 이유가 여기에는 걸리지 않는다.

Cloudflare Worker 도 아니다. 무료 계정의 정적 자산 배포는 그대로고
(CI 의 `bundle` 잡이 Worker 스크립트가 잡히면 붉어진다), 이 서버는 Docker 를
띄울 수 있는 어딘가에서 따로 도는 프로세스다.

## 무엇을 잃는가

**"고른 파일은 브라우저 밖으로 나가지 않는다" 가 이 기능에서만 깨진다.**
도구 전체의 성질이었던 것이 기능별 성질이 된다. 그래서 값을 치른다.

- 머리말 문구를 기능별로 바꿨다. "PDF 편집·HWPX 생성·읽기는 브라우저 안에서,
  HWP → PDF 만 변환 서버로 전송합니다."
- 전송 동의를 받기 전에는 변환 단추가 눌리지 않는다. 동의문에 보관 기한을 적는다.
- 원본은 변환이 끝나는 즉시 지우고, 결과는 15분 뒤 지운다. 화면은 내려받자마자
  서버 사본을 지운다. 작업마다 토큰이 있어 남의 작업을 조회할 수 없다.
- 변환은 매번 새 컨테이너에서 돈다 — 네트워크 없음, 읽기 전용 루트, 권한 전부
  제거, 메모리·CPU·프로세스·출력 크기 제한, 매크로와 외부 링크 갱신 차단.
- 서버 로그를 남기지 않는다. 문서 이름도 토큰도 적지 않는다.

## 무엇을 확인했는가

공개 HWP 5.0 문서 36건으로 실제 엔진을 돌렸다: 30건 변환, 2건 접수 거절(암호·배포용),
4건 변환 실패. 변환된 30건에서 **본문 글자가 한 줄도 빠지지 않았다** — 원본 HWP 의
문단 글자를 직접 읽어 PDF 에서 뽑은 글자와 순서까지 대조한다.

알려진 손실은 하나다. **그림·글상자의 캡션 글자가 빠진다.** 표 캡션은 나온다.
조용히 빠지므로 화면에 적었다. 실패하는 4건은 LibreOffice 프로세스가 문서를 읽다가
죽는 경우이고, API 는 그것을 실패로 알린다 — 절반짜리 PDF 를 성공으로 내주지 않는다.

이 검증이 두 결함을 잡았다: 필터를 강제 지정해 모든 변환이 실패하던 것과,
끝난 작업이 15분 동안 서버 자리를 물고 있어 16건 뒤로는 아무도 못 쓰던 것.

## 공개하기 전에 남은 것

- 한글이 내보낸 기준 PDF 와의 **배치 비교**. 컨테이너에 함초롬체가 없어 Noto CJK 로
  대체되므로 줄바꿈 위치가 달라진다. 이것을 재기 전에는 "보이는 그대로" 를 말할 수 없다.
- 실제 업무 문서와 동시 작업 부하.
- 운영 환경: TLS, 접근키(`HWP_SERVICE_KEY`, 루프백이 아니면 필수), 비용, 글꼴 사용 조건,
  H2Orestart 가 GPLv3 라는 사실에 따른 배포 형태 검토.

셋 중 하나라도 답이 없으면 공개하지 않는다. 그때도 데스크톱 경로는 남는다.
