# 결정 0014 — FIRE 계산기를 내린다

- 날짜: 2026-09-14
- 상태: **적용됨**
- 뒤집은 결정: [결정 0013](0013-deposit-products-from-fss.md)
- 관련 결정: [결정 0010](0010-retire-the-server-conversion-path.md),
  [결정 0012](0012-one-folder-per-feature.md)

## 결론

FIRE 계산기를 저장소에서 내린다. 탭은 **견적서**와 **문서 변환기** 둘만 남는다.

지우는 것: `fire/` 기능 폴더 전부(계산 모델·화면·예적금 상품 추천·공시 창구
Worker), 셸의 `web/worker/index.ts`, 그리고 그 기능을 세우던 배선 —
`web/index.html` 의 계산기 탭, `web/src/main.ts` 의 `@fire/view` 지연 적재,
`vite.config.ts`·`tsconfig.json`·`wrangler.jsonc` 의 `@fire` 별명,
`web/src/boundaries.test.ts` 의 `fire` 항목.

## 왜

저장소 주인이 이 도구를 더 두지 않기로 했다. 견적서 변환이 이 저장소의 일이고,
FIRE 계산기는 그것과 무관한 도구였다.

기능을 내리는 값이 싼 것은 결정 0012 덕분이다. 기능마다 최상위 폴더 하나라서
지울 것이 한 폴더와 셸의 배선 몇 줄로 끝났고, 남은 두 도구의 코드는 한 줄도
건드리지 않았다. `boundaries.test.ts` 가 기능끼리의 import 를 막아 온 덕에
"다른 데서 부르고 있지 않은가" 를 뒤질 일도 없었다.

## Worker 가 다시 사라진다

`wrangler.jsonc` 의 `main` 은 결정 0013 이 예적금 공시 중계 창구 때문에 세운
것이었다. 그 창구를 쓰던 기능이 없으므로 `main` 도, `alias` 도, 자산 손잡이
(`assets.binding`)도 함께 뺐다. 배포에 올라가는 것은 다시 정적 자산뿐이다.

그래서 결정 0002·0010 이 적어 둔 무료 계정 전제로 그대로 돌아간다.

| | |
|---|---|
| 요청당 CPU 한도 (10 ms) | 해당 없음 — Worker 스크립트가 없다 |
| 하루 요청 한도 (10만) | 쓰지 않음 — 정적 자산 요청은 무료·무제한 |
| Worker 스크립트 크기 (3 MiB) | 해당 없음 |

CI 의 `bundle` 잡도 결정 0010 때의 물음으로 돌아간다 — "Worker 스크립트가
잡히지 않는가". 여기 스크립트가 잡히면 전제가 깨진 것이다.

## 배포 대상에서 손볼 것은 없다

인증키(`FSS_API_KEY`)는 **어느 대상에도 올라간 적이 없다.** 결정 0013 이 적어
둔 `wrangler secret put` 은 상품 추천을 실제로 돌리려면 해야 할 일이었을 뿐이고,
그 단계까지 간 적이 없다. 그래서 지울 비밀도 없다.

혹시 나중에 넣어 둔 것이 있다면 그때 지운다 — 쓰지 않는 비밀을 남겨 두지 않는
것이 원칙이다.

```bash
cd web
npx wrangler secret list                     # 대상마다 무엇이 있는지 먼저 본다
npx wrangler secret delete FSS_API_KEY       # 있을 때만
```

## 무엇을 잃는가

**계산기 자체와, 공시에서 예적금을 받아 오던 창구를 잃는다.** 둘 다 돌아가던
것이었고 테스트도 있었다. 지우는 것이 아까운 코드지만, 쓰지 않는 기능을 켜 둔
채로 두면 남은 두 도구를 고칠 때마다 같이 지고 가야 한다.

되돌리는 값은 크지 않다. `fire/` 는 제 폴더 안에서 온전했으므로 커밋
`5307ef4` 에서 폴더째 되살리고, 셸의 배선(탭 한 줄·별명 한 줄·`main` 한 줄)을
다시 넣으면 선다. 공시 창구를 되살릴 때는 결정 0013 이 적어 둔 것 — 주소를
요청에서 조립하지 않는다, 실패 문구에 주소를 담지 않는다 — 을 그대로 지킨다.
