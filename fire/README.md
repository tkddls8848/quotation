# FIRE 계산기

모아 둔 돈과 앞으로의 저축, 은퇴한 뒤에 쓸 돈을 넣으면 **언제 일을 그만둘 수
있는지** 셈한다. 전부 브라우저 안에서 돈다 — 넣은 숫자는 서버로 가지 않는다.

```text
fire/web/src/
  model.ts            계산. DOM 도 브라우저 API 도 쓰지 않는다
  model.test.ts       계산이 맞는지 대조 (26가지)
  view.ts             화면 — 입력 항목 정의에서 폼을 만들고 결과를 그린다
  fire.css            이 기능 전용 스타일
  products.ts         금융감독원 예적금 공시 받아 오기·읽기
  products.test.ts    공시를 제대로 읽는지 대조 (7가지)
  recommend.ts        요건에 맞는 상품 고르기. 순수 계산
  recommend.test.ts   이자 셈과 차례가 맞는지 대조 (20가지)
  products-view.ts    상품 추천 칸
fire/worker/
  products.ts         공시 API 창구 — 인증키를 아는 유일한 자리 (셸이 세운다)
```

## 판정 방식

"25배를 모으면 끝"(4% 규칙)은 **참고선으로만** 보여 준다. 가능·불가 판정은 월
단위 모의 실험이 한다 — 은퇴 시점부터 기대 수명까지 매달 물가가 오른 만큼 더
쓰고, 남은 자산은 세후 수익률로 굴리고, 국민연금이 나오면 그만큼 덜 뽑는다.
그렇게 끝까지 자산이 남으면 "가능" 이다.

어림 대신 모의 실험을 쓰는 이유는 4% 규칙이 미국 주식·채권 60/40 을 30년 굴린
결과라서다. 한국의 예금·적금·채권 위주 자산, 물가, 15.4% 이자소득세, 65세부터
들어오는 국민연금은 그 전제와 다르다.

세금은 이자·배당 원천징수 15.4% 를 기본으로 보고, 한 해 금융소득이 2,000만원을
넘으면 초과분의 종합과세를 선택으로 반영한다. 국내 상장주식의 시세 차익은
소액주주 기준으로 비과세로 셈하므로, 해외 주식·ETF 라면 양도세 22% 만큼 상승률을
낮춰 넣어야 한다 (화면이 그 주의를 띄운다).

## 지금 가입할 수 있는 예적금 상품

"얼마를 모아야 하는가" 다음에 오는 물음은 "그 돈을 지금 어디에 넣는가" 다.
그래서 계산기 아래에 은행·저축은행의 정기예금과 적금을 놓고, 넣을 돈과 기간으로
**세금을 뗀 이자** 를 셈해 많이 주는 차례로 보여 준다.

금리를 이 저장소에 적어 두지 않는다. 적는 순간 낡기 때문이다. 금융감독원
**금융상품 통합 비교공시** 를 그때그때 받아 온다 (결정 0013).

### 금리가 아니라 세후 이자로 줄을 세우는 이유

- 단리와 월복리가 섞여 있다. 같은 3.5% 라도 받는 돈이 다르다.
- **적금은 회차마다 남은 개월만큼만 이자가 붙는다.** 월 100만원을 연 12% 짜리
  적금에 1년 넣으면 144만원이 아니라 78만원이다. 예금 금리와 적금 금리를 숫자
  그대로 견주면 반드시 틀린다.
- 이자소득세 15.4% 는 계산기 본체의 세율 항목을 그대로 받아 쓴다.

은행이 이자를 적어 주는 방식을 따라 **월이율은 연이율을 12 로 나눈 값**으로
셈한다. `model.ts` 의 `monthlyRate` 가 기하평균으로 환산하는 것과 다르다 — 거기는
수십 년을 굴리는 모의 실험이고 여기는 은행 창구의 셈법이라, 두 파일이 다른 것은
실수가 아니다.

### 이 칸은 계산기의 값을 바꾸지 않는다

세율 하나만 계산기에서 받아 쓰고, 반대 방향으로는 아무것도 흐르지 않는다. 공시
금리는 지금 가입할 수 있는 금리이고 계산기의 이율은 앞으로 수십 년의 가정이라,
둘은 같은 숫자가 아니기 때문이다.

### 돌려 보려면

공시 API 는 인증키를 요구하므로 `npm run dev` 만으로는 상품이 뜨지 않는다.
Worker 까지 세워야 한다.

```bash
cd web
printf 'FSS_API_KEY=받은키\n' > .dev.vars   # 추적하지 않는다
npm run build && npm run worker:dev        # 자산과 Worker 를 함께 세운다
```

키가 없으면 상품 칸만 안내 문구로 내려앉고 계산기는 그대로 돈다.

## 다른 기능과의 경계

- 다른 기능(`quotation/`, `converters/`)을 **부르지 않는다.** 반대도 마찬가지다.
- 셸(`web/`)이 `@fire` 별명으로 `web/src/view.ts` 의 `mountFire` 하나만 부른다.
  머리말·꼬리말·스타일까지 이 폴더가 갖는다.
- 셸의 Worker 도 `@fire/worker/products` 별명으로 `handleProducts` 하나만 부른다.
  공시 API 의 주소·응답 모양을 아는 것은 이 폴더뿐이다 (결정 0013).
- **기능 바깥에 공유 코드를 두지 않는다.** 다른 기능이 쓸 법한 것이라도 밖으로
  빼지 않고 여기 둔다. 공유는 이 폴더 안에서만 한다 — 밖에 둔 공유부는 거기
  생긴 문제 하나를 여러 기능의 장애로 번지게 한다 (결정 0012).

## 고칠 때

숫자가 틀리면 없느니만 못한 화면이라 계산을 화면에서 떼어 두었다. `model.ts` 를
고쳤으면 반드시 돌린다.

```bash
npm --prefix web test        # ../fire/web/src/*.test.ts 까지 함께 돈다
```

상품 쪽도 마찬가지다. 이자 셈이 틀리면 더 적게 주는 상품을 맨 위에 올려 놓게
되므로 `recommend.ts` 를 고쳤으면 반드시 돌린다.
